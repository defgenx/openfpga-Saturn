# Integration: Saturn on the Pocket top

Status: the whole design elaborates and synthesises in Quartus 21.1 (`quartus_map`), the glue is simulated
(`make -C sim platform`), nothing has run on hardware. The fitter does not fit it yet (section 7); the point of
this top is a complete netlist to measure and to cut against.

Files (all under `src/fpga/core/` unless noted):

| File | Role |
|---|---|
| `core_top.v` | APF top: bridge, data loader, settings, pad word, pin tri-states, scaler/I2S output |
| `saturn_pocket.sv` | the Saturn system: PLL + reconfiguration, resets, clock enables, `Saturn`, `mem_pocket`, `cdd_pocket`, pads, video, audio |
| `platform/pad_pocket.sv` | digital pad on the SMPC PIO ports |
| `platform/pocket_video.sv` | Saturn pixel stream to the APF scaler |
| `platform/pocket_audio.sv` | 44.1 kHz to 48 kHz resampler |
| `pll_sys/` | `altera_pll` (fractional, reconfigurable) and `altera_pll_reconfig`, generated by `tools/gen_pll_sys.sh` |
| `saturn_pocket.qip` | file list (the upstream `Saturn.qip` lists the ST-V files that are not imported) |
| `core_constraints.sdc` | clocks, CDC, multicycle, memory I/O |
| `src/fpga/rtl/`, `microrom.mem`, `nanorom.mem` | symlinks into `ref/Saturn_MiSTer` for the SH-1 / SMPC firmware images and the fx68k ROMs (the Saturn RTL opens `rtl/cdb105m.mif`, `rtl/Saturn/SMPC/smpc.mif` and `microrom.mem` relative to the project); the submodule must be checked out |

## 1. What is wired

`saturn_pocket` instantiates `Saturn` the way `ref/Saturn_MiSTer/Saturn.sv` does (`RAMH_SLOW=1`, no `STV_BUILD`, no
`DEBUG`), with the MiSTer framework replaced:

| MiSTer top | Pocket |
|---|---|
| `pll` + `pll_cfg` (50 MHz ref) | `pll_sys` + `pll_sys_cfg` from `clk_74a` |
| `sdram1`, `sdram2`, `ddram`, `vdp1_fb` (+ FB glue) | `mem_pocket` (docs/memory.md): SDRAM, 2 PSRAM, SRAM, M10K |
| `HPS2CDD`, `hps_ext`, `cdd_download`/`cdboot_download` | `cdd_pocket` (docs/cd.md); the disc header replay (`BOOT_*`) drives the same game-id / area / cartridge-request capture block |
| `hps_io` BIOS/cart download, `ioctl_wait` | `bridge_loader` -> `load_pocket` FIFO; `mem_pocket.loading` holds the Saturn in reset |
| `HPS2PAD` | `pad_pocket`: Digital pad only; same `joy1`/`joy2` word as the MiSTer top builds from `joystick_0/1` |
| `RTC` from `hps_io` | APF `rtc_date_bcd`/`rtc_time_bcd`, MSM6242B layout, toggle bit synchronised |
| OSD `status[]` | `interact.json`: Reset, Region (Auto/Japan/USA/Europe), Cartridge (Auto/None/RAM 1M/RAM 4M/Backup) |
| `video_mixer`, `cofi`, `video_freak`, light guns | `pocket_video` (the APF scaler does the rest) |
| `AUDIO_L/R` | `pocket_audio` -> `sound_i2s` |

Kept as in MiSTer: the clock enables (`SYS_CE_R/F`, `SCSP_CE`, `SMPC_CE`, `CD_CE`, `CDD_2X_CE`, all from `CEGen` with the
runtime `in_clk`), the WRAM-H write registers on `clk_ram` with the one-game patch, the region/PAL logic
(`area_code`, `PAL = area_code >= 0xA`), the `rst_ram` pulse after a load, `rst_sys = reset | download | rst_ram`.
Dropped: ST-V, DEBUG, light guns, mouse, keyboard, SNAC, 3D pad and the other pad types, `cofi`, crop, scanlines,
`FAST` and `BLUR_MESH` (tied 0), the HPS save sector state machine.

### Reset and settings

`core_top.sys_reset_n` = host reset, the interact Reset action (16 clk_74a stretch) and BIOS loaded
(`dataslot_allcomplete`). `saturn_pocket` adds "PLL has locked once" and synchronises the result into `clk_sys`.
The PLL relock caused by a dot-clock change does not reset the Saturn (as in MiSTer). Region 0 uses the area symbol
of the disc header; 1/2/3 force Japan (1), USA (4), Europe (0xC). `Cartridge` uses MiSTer's `cart_sel` values; Auto takes
the RAM cartridge request of the disc header (`mktoc.py --ramcart-db`).

### Switches for the other branches

`saturn_pocket.sv` has two compile switches, `POCKET_CUT_CD` (compiles out `cdd_pocket`, the `CD_*` ports of `Saturn` and
the CD RAM client; the cut's `Saturn.sv` interface is then edited in at the marked blocks) and `POCKET_CUT_SMPC`
(compiles out `pad_pocket`). Neither is defined and nothing behind them is implemented.

### Disc reads (`target_dataslot_*`)

`cdd_pocket` is the only client and drives the ports directly. A second client would need an arbiter; there is none
because backup RAM is saved by the host reading data slots 3/4 through the bridge (section 8), not by target writes.

## 2. Clock plan

One PLL, reference `clk_74a` (74.25 MHz), fractional-N, VCO about 640 to 687 MHz:

| Output | Divide | Frequency (NTSC 352, compile time) | Use |
|---|---|---|---|
| `outclk_0` `clk_sys` | 12 | 57.2728 MHz | all Saturn logic |
| `outclk_1` `clk_ram` | 6 | 114.5456 MHz | `mem_pocket`; exactly 2 x `clk_sys`, phase aligned |
| `outclk_2` `clk_vid` | 48 | 14.3182 MHz | APF `video_rgb_clock` (= `clk_sys` / 4) |
| `outclk_3` `clk_vid_90` | 48, +12 VCO cycles | same, +90 degrees | APF `video_rgb_clock_90` |

Runtime reconfiguration is kept (MiSTer's `pll_cfg` sequence: write M at address 4, K at 7, start at 2, `WAIT_FOR_LOCK`).
Only M and K change, so all four outputs scale together and the ratios, the 2:1 `clk_ram`, and the 90 degree phase (a
fixed number of VCO cycles) hold in every mode:

| Mode (`PAL`, `SMPC_DOTSEL`) | `clk_sys` | M | K (32 bit) | VCO |
|---|---|---|---|---|
| NTSC 320 | 53.7482 MHz | 8 (`0x404`) | `0xAFC38FAE` | 645.0 MHz |
| NTSC 352 | 57.2728 MHz | 9 (`0x20504`) | `0x4196FC35` | 687.3 MHz |
| PAL 320 | 53.3750 MHz | 8 | `0xA052BF5B` | 640.5 MHz |
| PAL 352 | 56.8750 MHz | 9 | `0x31219DBD` | 682.5 MHz |

These are exactly the `in_clk` constants of the MiSTer top, so `CEGen` ratios (SCSP, SMPC, CD, CDD, audio) are exact.
The default (NTSC 352) K is the value `ip-generate` computed for `pll_sys` (1100414005 = `0x4196FC35`), which checks the
register model; the reconfiguration itself, and VCO lock at 640 MHz on the -C8 part, are untested. The reference is
`clk_74a` for both the PLL and the audio side, so the 44.1 and 48 kHz rates stay locked to each other.

No fixed-clock fallback was needed; had reconfiguration failed, 57.27 MHz would run PAL and NTSC 320 content 6.5 %
(NTSC 320: 53.75 vs 57.27) and 0.7 % (PAL 352) too fast.

`pll_sys.v` was generated, not hand-written: `tools/gen_pll_sys.sh` runs `ip-generate` from the Quartus Docker image
(`altera_pll` with `gui_en_reconf`, `altera_pll_reconfig`).

## 3. Video

* `clk_vid` = `clk_sys` / 4. Hi-res (640/704) modes are one Saturn pixel per `clk_vid`; low-res pixels are held two clocks, so
  the picture is 640 or 704 wide in every mode and one clock is always one pixel (`video_skip` unused).
* The Saturn side registers pixel and syncs at `DCLK`; the `clk_vid` side samples them every clock (same PLL, so no
  FIFO). Pixel duration is 4 or 8 `clk_sys`, so each pixel is sampled once or twice, exactly.
* Scaler slots (`video.json`, six of the eight allowed), chosen per frame from `{VRES, HRES[0]}` latched at VBlank start
  (as MiSTer's `res`), written as `{8'h00, slot, 13'h0}` on the first clock after the last pixel of each line:

| Slot | Size | Slot | Size |
|---|---|---|---|
| 0 | 640x224 | 3 | 704x240 |
| 1 | 704x224 | 4 | 640x256 |
| 2 | 640x240 | 5 | 704x256 |

* 480i / 448i: each field is output as its own progressive frame at the field height (224/240/256 lines), no weave and
  no line buffer. It costs vertical resolution in interlaced double-density games (half the lines per frame, a
  one-line shift between fields) and nothing else; a woven 704x480 frame needs about 2.7 Mbit of buffer, more than the
  M10K that is left. A line-doubled 480-line frame would not look better than the scaler's own stretch of the field.
* HS is the Saturn HS delayed 4 `clk_vid` so that it is never closer than 3 clocks to VS; both are single-clock pulses.
* `make -C sim platform` (`tb_video`) checks DE length (640/704), lines per frame, pixel doubling, slot word, zero RGB
  outside DE and the HS/VS spacing for 320/352 low-res and 640/704 hi-res.

Not checked: that the scaler accepts a slot word at this position and a VS that falls in the middle of the Saturn's
VBlank (the generic template does the same), and refresh rate acceptance for PAL (about 50 Hz).

## 4. Audio

`pocket_audio` runs on `clk_sys`: a 44.1 kHz strobe (`SCSP_CE` / 512) shifts `{prev, cur}`; a 48 kHz phase accumulator
on `in_clk` triggers outputs, each `prev + (cur - prev) * ph` with `ph` advancing 44100/48000 per output and
shifted by one per input sample (a late input clamps, so a frequency error cannot run away). `sound_i2s` takes the result
with `clk_audio = clk_sys`. CD-DA is mixed into the SCSP input inside `Saturn`, so it goes through the same path.
`make -C sim platform` (`tb_audio`): 1 kHz in gives 1 kHz out at the right amplitude, residual -65 dB. One 16 x 17
multiplier, shared by both channels.

## 5. Constraints (`core_constraints.sdc`)

* `clk_74a`/`clk_74b`/`bridge_spiclk` and the PLL family are asynchronous groups; the PLL outputs are one synchronous
  family. The crossings are synchronisers, the gray FIFO of `load_pocket` and held payloads (cd_stream request registers).
* SH_core: setup 2 / hold 1 multicycle from and to `*|MSH|core|*` and `*|SSH|core|*` (docs/sh2.md: 19.6 ns path, advances
  on `CE_R` only).
* SDRAM: `dram_clk` generated (inverted `clk_ram`), output delays from the AS4C32M16MSA datasheet numbers in
  docs/memory.md, input delay 2.5 to 5.5 ns, 5-cycle multicycle for the READ+5/+6 capture. PSRAM: generated `clk_ram`/2 on the chip
  clock, 2 cycle multicycle for the read shift. SRAM: asynchronous, 3-cycle multicycle on the read data. All of these are
  starting values from datasheets as quoted in docs/memory.md; none has been checked against a timing report (the fit stops first).
