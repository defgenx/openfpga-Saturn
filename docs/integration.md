## 1. What is wired

`saturn_pocket` instantiates `Saturn` the way `ref/Saturn_MiSTer/Saturn.sv` does (`RAMH_SLOW=1`, no `STV_BUILD`, no
`DEBUG`), with the MiSTer framework replaced:

| MiSTer top | Pocket |
|---|---|
| `pll` + `pll_cfg` (50 MHz ref) | `pll_sys` + `pll_sys_cfg` from `clk_74a` |
| `sdram1`, `sdram2`, `ddram`, `vdp1_fb` (+ FB glue) | `mem_pocket` (docs/memory.md): SDRAM, 2 PSRAM, SRAM, M10K |
| `HPS2CDD`, `hps_ext`, `cdd_download`/`cdboot_download` | `cdd_pocket` (docs/cd.md); the disc header replay (`BOOT_*`) drives the same game-id / area / cartridge-request capture block |
| `hps_io` BIOS/cart download, `ioctl_wait` | `bridge_loader` -> `load_pocket` FIFO; `mem_pocket.loading` holds the Saturn in reset |
| `HPS2PAD` | `pad_pocket`: Digital pad only; same `joy1`/`joy2` word as the MiSTer top builds from `joystick_0/1` |
| `RTC` from `hps_io` | APF `rtc_date_bcd`/`rtc_time_bcd`, MSM6242B layout, toggle bit synchronised |
| OSD `status[]` | `interact.json`: Reset, Region (Auto/Japan/USA/Europe), Cartridge (Auto/None/RAM 1M/RAM 4M/Backup) |
| `video_mixer`, `cofi`, `video_freak`, light guns | `pocket_video` (the APF scaler does the rest) |
| `AUDIO_L/R` | `pocket_audio` -> `sound_i2s` |

Kept as in MiSTer: the clock enables (`SYS_CE_R/F`, `SCSP_CE`, `SMPC_CE`, `CD_CE`, `CDD_2X_CE`, all from `CEGen` with the
runtime `in_clk`), the WRAM-H write registers on `clk_ram` with the one-game patch, the region/PAL logic
(`area_code`, `PAL = area_code >= 0xA`), the `rst_ram` pulse after a load, `rst_sys = reset | download | rst_ram`.
Dropped: ST-V, DEBUG, light guns, mouse, keyboard, SNAC, 3D pad and the other pad types, `cofi`, crop, scanlines,
`FAST` and `BLUR_MESH` (tied 0), the HPS save sector state machine.

### Reset and settings

`core_top.sys_reset_n` = host reset, the interact Reset action (16 clk_74a stretch) and BIOS loaded
(`dataslot_allcomplete`). `saturn_pocket` adds "PLL has locked once" and synchronises the result into `clk_sys`.
The PLL relock caused by a dot-clock change does not reset the Saturn (as in MiSTer). Region 0 uses the area symbol
of the disc header; 1/2/3 force Japan (1), USA (4), Europe (0xC). `Cartridge` uses MiSTer's `cart_sel` values; Auto takes
the RAM cartridge request of the disc header (`mktoc.py --ramcart-db`).

### Host handshake

`core_top` drives the two status inputs of `core_bridge_cmd`:

| Input | Before Reset Exit | From Reset Exit to Reset Enter (`status_hold`) |
|---|---|---|
| boot done | `pll_locked_74a` | high |
| setup done | `pll_locked_74a & setup_ready_74a` | high |

- Before Reset Exit both follow the lock flag live, as v0.2.4 and the template do (`status_boot_done =
  pll_core_locked_s`). Request Status answers 2 ("setup") once the PLL is locked and 3 ("idle") at `setup_ready_74a`:
  the lock and the first `mem_ready` (`ever_ready`), or 2^17 clk_74a (1.77 ms) of lock if the RAM never reports ready.
  The rising setup done queues Ready to Run (0x0140).
- `status_hold` sets in the first clk_74a after Reset Exit with setup done high and clears at Reset Enter
  (`status_running` low). While it is set both inputs stay high, so the `pll_lite` relock of a PAL or dot-clock change
  (SMPC CKCHG320/352) never makes Request Status answer 1 or 2 mid-game.
- `core_bridge_cmd` queues Ready to Run only while `status_running` is low. A second 0x0140 while running would wait
  for an `ok` the host never sends, and every later disc read (0x0180) would queue behind it in
  `TARG_ST_WAITRESULT_RTR`.

Why nothing is held before Reset Exit: v0.2.5 and v0.2.6 made both inputs sticky from the first lock / RAM ready (with
a lock-hold gate on the RAM init and a 512-word load FIFO), and the Pocket rejected both with "core not ready to run",
while v0.2.4 starts. The boot side up to Reset Exit is v0.2.4's: `core_bridge_cmd.v` (RTC outputs wired to the
parameter registers 0x24 / 0x28), `saturn_pocket`'s readiness, the RAM init from configuration, the 256-entry load FIFO.

**Load FIFO.** The host may push slot 0 as soon as the status is 2, at one word per 88 clk_74a or more
(`io_bridge_peripheral.v`), and the bridge has no back-pressure. `load_pocket` holds 256 words (one M10K). In `tb_sys`
with the BIOS (host pushing at 88 clk_74a per word from the moment the status leaves 1) the status is 2 at 0.24 us and
3 at 230 us; 186 words arrive before the RAM is ready, at most 185 are in flight, no overflow.

**Checks.** `sim/platform/tb_bridge_status.sv` (`make -C sim platform`) runs the real `core_bridge_cmd` with the
expressions above through a relock 1.6 ms after Reset Exit: the host must see 2 before the RAM is ready, then 3,
exactly one Ready to Run and no status 1/2 while running. `-DLIVE` (the lock flag live throughout) answers 1/2 five times
during the relock and fails. In `tb_sys`, `sim/sys/models/pll_sim.sv` drops the lock for 20 us on every mode change,
`+RELOCK_US=<t>` adds one such drop at t us and `+FLICKER_*` adds chatter; the trace logs `PLL locked` and `STATUS`
changes. With BIOS and disc, `+RELOCK_US=80000` (20 ms after Reset Exit) leaves both status inputs high.

### Switches for the other branches

`saturn_pocket.sv` has two compile switches, `POCKET_CUT_CD` (compiles out `cdd_pocket`, the `CD_*` ports of `Saturn` and
the CD RAM client; the cut's `Saturn.sv` interface is then edited in at the marked blocks) and `POCKET_CUT_SMPC`
(compiles out `pad_pocket`). Neither is defined and nothing behind them is implemented.

### Disc reads (`target_dataslot_*`)

`cdd_pocket` is the only client and drives the ports directly. A second client would need an arbiter; there is none
because backup RAM is saved by the host reading data slots 3/4 through the bridge (section 8), not by target writes.

## 2. Clock plan

MiSTer's PLL plan, adapted to the 74.25 MHz reference. One fractional-N PLL from `clk_74a`, generated by
`tools/gen_pll_sys.sh`; the numbers below are printed by `tools/pllplan.py`.

### MiSTer's plan

`Saturn_MiSTer/rtl/pll/pll_0002.v` (50 MHz reference) uses the VCO post-divider (`pll_vco_div` 2): the M counter and the
output counters run on VCO / 2. `clk_sys` is counter 8, `clk_ram` counter 4, so VCO / 2 = 8 x `clk_sys` and the VCO is
16 x `clk_sys`. Charge pump 20 uA, loop resistor (`pll_bwctrl`) 4000, N bypassed, 1st-order delta-sigma, 32-bit K.
The reconfiguration writer (`Saturn.sv` 440-466) writes M and K on every PAL / dot-clock change and at reset.

Ours keeps all of it. Only M + K changes with the reference: M + K = 8 x `clk_sys` / 74.25, and the VCO is the same as
MiSTer's in every mode.

| Mode (`PAL`, `SMPC_DOTSEL`) | `clk_sys` (Saturn.sv `in_clk`) | VCO | M + K | M (hi + lo) | M reg (mgmt addr 4) | K (32 bit) | MiSTer M + K |
|---|---|---|---|---|---|---|---|
| NTSC 320 | 53.7482 MHz | 859.97 MHz | 5.7911 | 5 (3 + 2, odd) | `0x20302` | `0xCA825FC9` | 8.5997 |
| NTSC 352 | 57.2728 MHz | 916.36 MHz | 6.1708 | 6 (3 + 3) | `0x00303` | `0x2BB9FD78` | 9.1636 |
| PAL 320 | 53.3750 MHz | 854.00 MHz | 5.7508 | 5 (3 + 2, odd) | `0x20302` | `0xC0372A3C` | 8.5400 |
| PAL 352 | 56.8750 MHz | 910.00 MHz | 6.1279 | 6 (3 + 3) | `0x00303` | `0x20C113D3` | 9.1000 |

M switches between 5 and 6 as MiSTer's between 8 and 9. The 32-bit K puts `clk_sys` within 0.001 ppm of `in_clk`, so the
`CEGen` ratios (SCSP, SMPC, CD, CDD, audio) are exact.

Outputs (counters on VCO / 2; phases are counter-input eighths, fixed in degrees across modes):

| Output | Counter | Frequency (NTSC 352, compiled) | Phase | Use |
|---|---|---|---|---|
| `outclk_0` `clk_sys` | 8 (4 + 4) | 57.2728 MHz | 0 | all Saturn logic |
| `outclk_1` `clk_ram` | 4 (2 + 2) | 114.5456 MHz | 0 | `mem_pocket`; exactly 2 x `clk_sys`, phase aligned |
| `outclk_2` `clk_vid` | 32 (16 + 16) | 14.3182 MHz | 0 | APF `video_rgb_clock` (= `clk_sys` / 4) |
| `outclk_3` `clk_vid_90` | 32 | same | 90 degrees (prst 9) | APF `video_rgb_clock_90` |
| `outclk_4` `clk_ram_cap` | 4 | 114.5456 MHz | 90 degrees (prst 2) | unused since the IOE SDRAM capture; kept as before |

`operation_mode` stays `normal` (MiSTer's is `direct`): our SDC and the counter placement were closed with the
compensated feedback, and nothing in the plan needs direct mode.

### Limits checked

- K: ip-generate rejects K outside 0.05 .. 0.95 (`altera_pll` `pll_hw_extra.tcl`, "fractional multiplication factor
  outside of the legal range"). Our margins are 0.159 / 0.121 / 0.199 / 0.078 (NTSC 320 / NTSC 352 / PAL 320 / PAL 352);
  the smallest is PAL 352 (K 0.128).
- VCO: 854 .. 916 MHz, inside the Cyclone V -C8 range of 600 .. 1300 MHz (the old plan ran 640 .. 687 MHz).
- Loop: the fitter reports a loop bandwidth of 1.5 .. 2.0 MHz for M 6 and for M 5, against 1.4 .. 2.1 MHz for MiSTer's
  M 9 at 50 MHz. That is the same normalised loop: the counter input (M x fPFD = 8 x `clk_sys`) and the VCO are MiSTer's,
  so charge pump 20 / resistor 4000 serve both M values here as they serve 8 and 9 there. Reference lock range
  (fitter): 50 .. 105.3 MHz at M 6, 51.8 .. 112.2 MHz at M 5; 74.25 MHz is inside both.
- Fitter PLL summary, compiled mode: M 6, N 1, K 733609336 / 2^32, counters 8 / 4 / 32 / 32 (prst 9) / 4 (prst 2).
  Its "PLL VCO Frequency" line is the post-divided 458.18 MHz (the same line reads 458.18 MHz for MiSTer's plan); the
  lock range 1300 / (2 x 6.1708) = 105.3 MHz shows the factor 2.

### How `pll_sys.v` is generated

ip-generate never picks the post-divider 2 at 74.25 MHz: in frequency mode it chooses VCO 687 MHz, M 9, divider 1 (the old
plan). Its physical-parameter mode has no post-divider entry, so M 6 there fails with "VCO beyond the limit". So
`gen_pll_sys.sh` asks ip-generate for our five clocks at MiSTer's 50 MHz reference. That gives exactly MiSTer's
physical plan with our counters: post-divider 2, C 8 / 4 / 32 / 32 / 4, the phases, cp 20, bwctrl 4000.
`pllplan.py --patch` then checks those values and replaces only the reference frequency, M (hi, lo, odd), K and the
frequency strings with the compiled mode's. The PLL is compiled in NTSC 352, the fastest mode, so STA covers the worst case.

### Runtime reconfiguration

`pll_lite` (`POCKET_PLL_LITE`, set in `ap_core.qsf`) replaces `altera_pll_reconfig` (737 ALMs) with the same DPRIO
sequence for an M + K write. M at 0x12 {hi, lo}; read-modify-write of 0x15 bit 4 (M bypass, 0) and 0x17 bit 4
(M odd = 320); then K: 0x17 with K-ready low, 0x18 / 0x19, 0x17 with K-ready high. It runs at the first lock, at every
host reset and on every mode change. The C counters are never written, so the outputs keep their ratios, the 2:1
`clk_ram` and the phases in every mode. The Saturn is not reset or held on a relock, as in MiSTer.

`sim/pll` (`make -C sim pll`) runs it against `pll_sys_cfg` driven with MiSTer's mgmt sequence (M at 4, K at 7, start at
2). `tb_pll_lite` checks the final DPRIO registers after NTSC 352, NTSC 320, PAL 352, PAL 320, NTSC 352 and PAL 352.
`tb_bus` + `bus_diff.py` check the full `reconfig_to_pll` bus access by access from power-up through all four modes:
the DPRIO init is identical, and every burst is identical. The non-`POCKET_PLL_LITE` branch of `saturn_pocket.sv` is
that same mgmt writer with the same constants.

`POCKET_FIXED_352` is a diagnostic build that pins the PLL and the CE mode to 352 (docs/debug-overlay.md).

The reference is `clk_74a` for both the PLL and the audio side, so the 44.1 and 48 kHz rates stay locked to each other.

## 3. Video

* `clk_vid` = `clk_sys` / 4. Hi-res (640/704) modes are one Saturn pixel per `clk_vid`; low-res pixels are held two clocks, so
  the picture is 640 or 704 wide in every mode and one clock is always one pixel (`video_skip` unused).
* The Saturn side registers pixel and syncs at `DCLK`; the `clk_vid` side samples them every clock (same PLL, so no
  FIFO). Pixel duration is 4 or 8 `clk_sys`, so each pixel is sampled once or twice, exactly.
* Scaler slots (`video.json`, six of the eight allowed), chosen per frame from `{VRES, HRES[0]}` latched at VBlank start
  (as MiSTer's `res`), written as `{8'h00, slot, 13'h0}` on the first clock after the last pixel of each line:

| Slot | Size | Slot | Size |
|---|---|---|---|
| 0 | 640x224 | 3 | 704x240 |
| 1 | 704x224 | 4 | 640x256 |
| 2 | 640x240 | 5 | 704x256 |

* 480i / 448i: each field is output as its own progressive frame at the field height (224/240/256 lines), no weave and
  no line buffer. It costs vertical resolution in interlaced double-density games (half the lines per frame, a
  one-line shift between fields) and nothing else; a woven 704x480 frame needs about 2.7 Mbit of buffer, more than the
  M10K that is left. A line-doubled 480-line frame would not look better than the scaler's own stretch of the field.
* HS is the Saturn HS delayed 4 `clk_vid` so that it is never closer than 3 clocks to VS; both are single-clock pulses.
* `make -C sim platform` (`tb_video`) checks DE length (640/704), lines per frame, pixel doubling, slot word, zero RGB
  outside DE and the HS/VS spacing for 320/352 low-res and 640/704 hi-res.

Not checked: that the scaler accepts a slot word at this position and a VS that falls in the middle of the Saturn's
VBlank (the generic template does the same), and refresh rate acceptance for PAL (about 50 Hz).

## 4. Audio

`pocket_audio` runs on `clk_sys`: a 44.1 kHz strobe (`SCSP_CE` / 512) shifts `{prev, cur}`; a 48 kHz phase accumulator
on `in_clk` triggers outputs, each `prev + (cur - prev) * ph` with `ph` advancing 44100/48000 per output and
shifted by one per input sample (a late input clamps, so a frequency error cannot run away). `sound_i2s` takes the result
with `clk_audio = clk_sys`. CD-DA is mixed into the SCSP input inside `Saturn`, so it goes through the same path.
`make -C sim platform` (`tb_audio`): 1 kHz in gives 1 kHz out at the right amplitude, residual -65 dB. One 16 x 17
multiplier, shared by both channels.

## 5. Constraints (`core_constraints.sdc`)

* `clk_74a`/`clk_74b`/`bridge_spiclk` and the PLL family are asynchronous groups; the PLL outputs are one synchronous
  family. The crossings are synchronisers, the gray FIFO of `load_pocket` and held payloads (cd_stream request registers).
* SH_core: setup 2 / hold 1 multicycle from and to `*|MSH|core|*` and `*|SSH|core|*` (docs/sh2.md: 19.6 ns path, advances
  on `CE_R` only).
* The PLL clock names the fitter derives are `ic|saturn|pll|altera_pll_i|cyclonev_pll|counter[N].output_counter|divclk`
  (not the `general[N].gpll~...` names of the template); all clocks and generated clocks resolve (checked with
  `quartus_sta` post-map). The template reads `core_constraints.sdc` twice, which makes the timing analyzer warn
  about replaced delays; the values are identical.
* SDRAM: `dram_clk` generated (inverted `clk_ram`), output delays from the AS4C32M16MSA datasheet numbers in
  docs/memory.md, input delay 2.5 to 5.5 ns, 5-cycle multicycle for the READ+5/+6 capture. PSRAM: generated `clk_ram`/2 on the chip
  clock, 2 cycle multicycle for the read shift. SRAM: asynchronous, 3-cycle multicycle on the read data. All of these are
  starting values from datasheets as quoted in docs/memory.md; none has been checked against a timing report (the fit stops first).

## 6. Simulation and lint

| Check | Result |
|---|---|
| `make -C sim platform` | audio (1 kHz, -65 dB residual) and four video modes pass |
| `make -C sim mem` | passes with the two `vdp1_fb_pocket` changes of this branch (section 7) |
| `make -C sim irq` | `sh2p`+`DCC`+`SMPC_SERV`+`SCUP2` wired as in `Saturn.sv`, build macros: SNDON through SF/COMREG on the real bus, then VBLANK-IN/OUT interrupts (IMS, ICR.VECMD, vector fetch) delivered; negative control with IVECF# stuck low fails; `Saturn.sv` has no port connected twice |
| `quartus_sh --flow compile ap_core` (21.1, 5CEBA4F23C8) | analysis and synthesis succeed, 159 warnings, no error; the fitter fails on capacity |
| `quartus_sta` post-map with the SDC | PLL clocks, generated clocks and groups resolve |

`Saturn.sv` connected `.IVECF_N` of the master SH-2 twice (`.IVECF_N(MSHIVECF_N)` and a later `.IVECF_N()`, inherited from
the MiSTer source). Verilator and Quartus 17 take the first; a tool that takes the last leaves `MSHIVECF_N` undriven (0):
the SCU then sees a vector fetch on every read and resets IMS to its masked value after each one, so no interrupt is ever
raised (`make -C sim irq neg`), as with the black screen where the BIOS never unmasks an interrupt. The empty connection
is removed; `sim/irq/dup_ports.py` fails on any such duplicate.

The Verilator lint of the glue modules (`verilator --lint-only -Wall`) is clean apart from unused-bit notes. The full
tree is checked by Quartus, not Verilator (it needs the Altera RAM/PLL primitives).

Two fixes were needed to synthesise at all, both in `mem/vdp1_fb_pocket.sv`: the FB1 array (90112 x 16) did not infer
as RAM and became registers (an internal error in `opt_op_decsel` after 2.5 hours, or "registers exceed the device"), so it is
now an `altsyncram` (M10K, byte enables) with a behavioural copy for simulation; and the FB0 write FIFO had an
asynchronous read (8960 registers), now a synchronous read plus a one-clock-late `wptr` so that it maps to one M10K.

## 8. Remaining gaps

* Does not fit (section 7), so there is no timing report. The SDC I/O values are starting points; the SDRAM capture
  edge, PSRAM `READ_ADJ`/`WRITE_ADJ` and the SRAM cycle counts need hardware.
* Backup RAM and backup cartridge: loaded from the bridge, but the read-back for saving (`bk_rd_data` at `0x4xxxxxxx` /
  `0x5xxxxxxx`) is still zero, so nothing is saved. Cartridge ROM has no data slot.
* Pads: Digital only. No 3D/analog pad, mouse, or six-button remap beyond core_top's `pad2saturn`; player 2 uses `cont2`.
* `cfg_cart` Backup selects the backup cart type, but its save file cannot be written (above). No "CD speed" setting:
  the drive speed follows the BIOS command (the old interact entry was replaced by Cartridge).
* Video: field-per-frame for interlaced content; the slot word position and 90 degree clock handling are untested on a scaler.
  PAL 256-line modes are mapped to the 640x256/704x256 slots; the scaler's PAL refresh handling is unchecked.
* PLL reconfiguration (M 5 / 6, VCO 854 .. 916 MHz, section 2) and that `clk_ram` stays aligned after it are untested
  on hardware; the Saturn is not reset on a relock (as MiSTer).
* No resource arbitration for a second `target_dataslot_*` client.
* Interact reset action and `bios_loaded` start/stop sequencing (including `dataslot_allcomplete` with deferred disc
  slots) are unchanged from the template and untested.
* The `POCKET_CUT_CD` / `POCKET_CUT_SMPC` switches only compile things out; the replacement blocks belong to the cuts.
