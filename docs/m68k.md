# 68K sound CPU for the Pocket

Scope: `src/fpga/saturn/M68KP/` (the 68000 selected by `POCKET_M68KP`), `sim/m68k/`, `sizing/m68k/`. Budget from
[status.md](status.md): 1,654 fitter ALMs in the integrate build, goal 1,000. **Result: 986 fitter ALMs standalone
against 1,986 for FX68K in the same flow, cycle-exact with FX68K (not an approximation).**

## 1. Result

Standalone `quartus_fit`, Quartus 21.1.1 (`raetro/quartus:21.1`), area profile of `sizing/area_profile.qsf`,
`NUM_PARALLEL_PROCESSORS 1`, Cyclone V 5CEBA4F23C8, top `sizing/m68k/m68k_wrap.sv` (the 68K as connected in
`Saturn.sv`, `BR/BGACK/BERR/HALT` tied inactive, every port a virtual pin).

| Revision | map ALM (est.) | **fit ALM** | ALUT | regs | RAM blocks | MLAB bits | setup Fmax |
|---|---|---|---|---|---|---|---|
| FX68K (golden, `src/fpga/saturn/FX68K`) | 2,093 | **1,986** | 2,886 | 1,388 | 6 | 0 | 94.9 MHz |
| m68kp, MLAB register file | 1,291 | 1,343 | 1,987 | 847 | 6 | 2,048 | |
| m68kp, ROM decode too (**shipped default**) | 938 | **986** | 1,433 | 851 | 11 | 2,048 | 120.7 MHz |
| m68kp with `M68KP_REGS_M10K` (not recommended) | 950 | 972 | 1,495 | 951 | 17 | 0 | |

In context (SCSP + 68K wired as in `Saturn.sv`, `sizing/m68k/scsp68_wrap.sv`, same SCSP source for both): SCSP + FX68K
4,196 fit ALMs (36 RAM blocks), SCSP + m68kp 3,106 (41 blocks): the swap saves 1,090 ALMs in the neighbourhood of the
block it talks to. The `status.md` figure of 1,654 for FX68K is the in-system fit and 1,986 the standalone one; scaling
by the standalone ratio (0.50) or subtracting the in-context saving gives roughly 820 or 560 ALMs in the integrate
build (not measured there).

The map-stage estimate understates designs with MLAB (the six register-file MLABs, 60 ALMs, appear only in the fit).
Setup timing is the worst reg-to-reg slack at 57.27 MHz with the FX68K multicycle constraints (`m68kp.sdc`),
`sizing/m68k/sta.sh`; the worst path is the ALU CCR logic, +9.2 ns of slack.

Cost: **+5 M10K** (the decode ROMs) and 2,048 MLAB bits; nothing else changes. `M68KP_PLA_LOGIC` gives back the
original combinational PLA (1,343 ALMs, 6 blocks), `M68KP_REGS_M10K` moves the register file from MLAB to M10K (972 ALMs, 17 blocks: each of the six RAMs takes a block).

## 2. How the Saturn uses the 68K

From `Saturn.sv` and `SCSP.sv`:

- The 68K clock is `SCCE_R`/`SCCE_F` of the SCSP: strobes on every `SCSP_CE` (22.5792 MHz), alternating, so the 68K
  runs at 11.2896 MHz. `clk_sys` is 57.27 MHz (NTSC 352), **5.07 `clk_sys` per 68K clock**, 2.54 per half clock.
  The strobes are 2 or 3 `clk_sys` apart, never closer (53.4-57.3 MHz `in_clk` in all video modes).
- `BR`, `BGACK`, `BERR`, `HALT` are tied inactive; `E`/`VMA` unconnected. `VPAn = ~&FC` (every interrupt acknowledge
  is an autovector); `IPL = ~ILV` from the SCSP interrupt controller. `DTACK` comes from the SCSP and is
  asserted after the sound RAM / register access completes, so wait states depend on PCM/DSP RAM slots.
- `extReset = ~SCPU_RES_N | ~M68K_RESO_N`: the RESET instruction resets the CPU itself.
- The 68K runs game-supplied sound driver code, so the whole user ISA, the exceptions and the timing it can observe stay.

| (c) multi-cycle microcoded core on the 5 `clk_sys` per 68K clock | see J68 | | | | |

(b): the cores were measured as shipped except J68, whose `altsyncram` instances (Cyclone III parameters, rejected by
Cyclone V) were replaced by an inferred ROM plus a 64-word register RAM (`M68KP/j68/`, ISC). Without that split the
inferred RAM turned into 3,048 ALMs of logic; with it 1,433 ALMs. TG68K and ao68000 raw numbers have no bus adapter
either, which would add to them. Their accuracy is judged from their own documentation, not measured. J68 ships in the
tree only because it was measured (ISC, GPL-3.0 compatible); nothing selects it. TG68K.C (LGPL-3.0-or-later) and
ao68000 (BSD-2-Clause) are not vendored (`sizing/m68k/fetch_cores.sh` clones them for the measurement).

(c) J68 is exactly that design (a serial stack-machine microcode on a 16-bit datapath running several clocks per
68K clock) and it is not smaller than 1,400 ALMs; a new one would have to beat it by 30% while reproducing 68000
bus timing, for no gain over a core that is already exact.

## 4. The design

`m68kp` is a copy of FX68K (module names prefixed `mp_`, macros `MP_`, so both can be compiled together) with two
structural changes. Nothing in the microcode, nanocode, ALU, sequencer or bus control changed.

**Register file (-643 fit ALMs).** FX68K keeps D0-D7, A0-A6, USP, SSP and a temporary in 18 x 32 flip-flops with four
18:1 read multiplexers and two write ports. It is now six 32-word RAMs (`mp_regram8`/`mp_regram16`: two copies, one per
read port, each as low byte / high byte / high word because of the byte writes to data registers), asynchronous read
(MLAB) by `actualRx`/`actualRy` as before. The two writes of one `enT3` (Rx and Ry) go to the single write port in
consecutive clocks, Rx first and Ry in the next clock (`stepB`), which keeps "Ry wins" when both name the same register.
This works because the buses, `actualRx/Ry`, `rxIsAreg/ryIsAreg` and `abdIsByte` only change on `enT2`/`enT4`,
at least two `clk_sys` after `enT3`, and the registers are only read at `enT1`. **Assumption: `enPhi1`/`enPhi2`
at least two `clk_sys` apart** (true in the Saturn, section 2; the bench shows the divergence at spacing 1,
`PERIOD=1`). With `M68KP_REGS_M10K` the read address is registered (one more clock, still before `enT1`).

**Opcode decode (-357 fit ALMs, +5 M10K).** `uaddrDecode` is a 16-bit-in, 34-bit-out PLA (555 ALUT). Its 65,536 outputs
contain 505 distinct (a1, a2, a3) triples and 89 distinct columns over the EA field, so it is three ROMs:
`opcode[15:6]` -> column (1,024 x 7), `{column, EA class}` -> triple + illegal flag (2,048 x 10), triple -> a1/a2/a3
(505 x 30), with a 64-entry side table for 4E40-4E7F (all six low bits matter) and an EA class for "low six bits
zero" (Bcc displacement 0). `sim/m68k/gen_pla_rom.py` generates `m68kp_plarom.sv` from the original PLA
(`make plarom`) and checks the reconstruction for all 65,536 opcodes; `make run_pla` re-checks the synthesised RTL
against the original (0 of 65,536 differ). `isPriv`, `isLineA/F` stay as logic. The decode takes three `clk_sys` after
`Ir` changes (at `enT1`), its first consumers sample at `enT3` (at least four `clk_sys` later); `enT1` of the next
microinstruction is at least eight later.

The result stays 1:1 with FX68K, including the odd cases (address error cycle, TAS, MOVEP), so none of the
"drop what the sound CPU never uses" cuts were taken: with the register file and the PLA gone the remainder
(ALU 376 ALUT, bus multiplexers ~450, sequencer 73, nano decoder 49) is what a 68000 needs and what the drivers can hit.
Bus arbitration, BERR/HALT and E/VMA are already removed by the tie-offs of `Saturn.sv`.

## 5. Verification (`sim/m68k/`, Verilator 5)

Golden `REF_fx68k` (generated by `rename.py` from `ref/Saturn_MiSTer/rtl/FX68K`) and `m68kp` get the same pins; the bench
compares every output pin (address, data when written, AS/UDS/LDS/RW, FC, E, VMA, BG, RESET, HALT) **every
`clk_sys`**, so bus cycle address, data, function code and timing are all covered with zero tolerance.

| Test | Stimulus | Result |
|---|---|---|
| `make run_pla` | all 65,536 opcodes, ROM decode vs PLA | 0 differ |
| `make run_sst` | SingleStepTests 68000 v1, 24,800 cases (200 per instruction file, all 125 files) through a register loader (MOVE.L/MOVEA.L/MOVE USP/RTE from a separate memory image), SCSP-like strobe pattern, no wait states; the same cases with random DTACK delays of up to 4 clocks (the suite has none, so its checks fail on timing and only the lockstep verdict counts), and with fixed strobe spacing 3; the first 4,960 also with spacing 2 and 4 | 0 lockstep failures in all runs, registers + SR compared at the end of each instruction as well |
| `make run_img` | 60 generated sound-driver-like programs (`gen_prog.py`: byte/word ALU, bit ops, tables via (An)+/d8(An,Xn), MOVEM/MOVEP, MUL/DIV, shifts, DBRA loops, JSR/RTS, TRAP and illegal-opcode handlers, random IPL and wait states) | 0 mismatches |
| `make run_sys` | golden SCSP + 68K as in `Saturn.sv`, FX68K vs m68kp, programs that start timer A and take the autovector interrupt (286 interrupts per 3M clk), slot register traffic; compares 68K pins, IPL, sound RAM interface and audio | 0 mismatches |

Negative controls: breaking one line of the register file (`mutate.sh`) gives 523 lockstep failures in the SST run; strobes
one `clk` apart (`PERIOD=1`) make every test diverge.

The same SST run also checks the golden FX68K against the suite (bus cycle list and kinds, FC, addresses, write data,
timing between bus cycles, final registers, SR, memory; `TAS` timing only). On the 24,800 cases FX68K disagrees with
the suite on 567 of 19,972 non-exception cases (2.8%) and on 4,519 of 4,828 exception-path cases. The golden core is the
reference here, so these are reported, not tolerated; the DUT reproduces every one of them identically.

| Class (non-exception) | cases | what differs |
|---|---|---|
| RTE/RTR | 195 | pop order of the stack words (suite: PC high first; FX68K: SR/CCR first) |
| PC-relative operand | 127 | FC 6 (program space, as the 68000 does) vs the suite's 5 |
| DIVU/DIVS final CCR | 83 | CCR after the division (not analysed further) |
| shift/rotate final CCR | 72 | CCR, e.g. ASR.b by 13: FX68K sets X/C, suite does not |
| TAS | 32 | read-modify-write is 2 clocks shorter |
| DIVU/DIVS timing | 26 | cycle count (about 120 clocks apart in the cases seen; not analysed) |
| LINK A7 | 20 | value pushed |
| CHK exception timing | 11 | 6 clocks around the trap |

Exception path (address error from random operand addresses, CHK, DIV by zero, TRAP, illegal): FX68K asserts AS for
the faulting access (a bus read the suite does not have) before writing the frame, and the cycle counts that follow
differ (2,138 timing, 2,129 "write expected, read got").

## 6. Deviations from FX68K

None observable at the pins, with the stated assumption on strobe spacing (>= 2 `clk_sys`) and these notes:

- the opcode decode result is available three `clk_sys` after `Ir` changes instead of combinationally (always
  consumed later);
- RAM blocks: 6 -> 11 (M10K), MLAB 6 blocks;
- registers are not initialised at power-up, as in FX68K (software must not read an unwritten register).

## 7. Using it

- Build with `POCKET_M68KP` defined (`src/fpga/core/saturn_pocket.qip` already lists `M68KP/m68kp.qip`; without the
  macro `Saturn.sv` instantiates `fx68k` and the new files are unused). `microrom.mem` and `nanorom.mem` must be in the
  project directory, as for FX68K.
- `M68KP_PLA_LOGIC` selects the original PLA (no M10K); `M68KP_REGS_M10K` the M10K register file (measured: -14 ALMs for +6 blocks, not worth it).
- `make -C sim/m68k lock run_pla run_img run_sys` (SST: `python3 sim/m68k/sst2txt.py tests.txt 200 .../68000/v1/*.json.gz`,
  then `make run_sst SST=tests.txt`; `sizing/m68k/fetch_cores.sh` clones the suite).
